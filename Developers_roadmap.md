## ЭТАП 1 — Фундамент проекта
*Цель: рабочий скелет приложения с базой данных и авторизацией*
### Шаг 1.1 — Инициализация проекта
```
Создай новый Next.js 14 проект с TypeScript и Tailwind CSS под названием "tilitili-flashcards".
Настрой структуру папок: src/app, src/components/ui, src/components/quiz, src/components/admin, src/lib, src/types.
Добавь .env.example с переменными DATABASE_URL, JWT_SECRET, NEXT_PUBLIC_APP_URL.
Установи зависимости: prisma, @prisma/client, bcryptjs, jsonwebtoken, @types/bcryptjs, @types/jsonwebtoken.
```
### Шаг 1.2 — Схема базы данных
```
Создай Prisma схему для PostgreSQL со следующими моделями:
- User (id, username, passwordHash, role: ENUM[USER, EDITOR, ADMIN], xp, level, createdAt)
- Word (id, kyrgyz, russian, type: ENUM[WORD, PHRASE, IDIOM], topic, pos, difficulty 1-3, createdAt)
- UserWordStat (id, userId, wordId, shown, correct, incorrect, lastShownAt)
- UserTopicProgress (id, userId, topic, completed, bestScore, completedAt)
- Session (id, userId, mode, score, totalQuestions, xpEarned, createdAt)
Примени миграцию и добавь seed-файл с первыми 20 словами (кыргызский-русский) по 2 топикам.
```
### Шаг 1.3 — Авторизация: API
```
Создай API роуты в Next.js для авторизации:
- POST /api/auth/register — принимает username и password, валидирует (username мин 3 символа, пароль мин 6), хэширует пароль через bcrypt, создаёт пользователя, возвращает JWT токен
- POST /api/auth/login — проверяет username/пароль, возвращает JWT токен
- GET /api/auth/me — возвращает данные текущего пользователя по JWT из заголовка
Создай middleware для проверки JWT на защищённых роутах.
Создай утилиты в src/lib/auth.ts: signToken, verifyToken, hashPassword, comparePassword.
```
### Шаг 1.4 — Авторизация: UI
```
Создай страницы авторизации в Next.js App Router:
- /login — форма с полями username и password, кнопка "Войти", ссылка на регистрацию
- /register — форма с полями username и password, кнопка "Зарегистрироваться", ссылка на вход
Добавь валидацию полей, отображение ошибок (неверный пароль, занятый username и тд).
Сохраняй JWT в httpOnly cookie.
После входа редирект на /dashboard.
Дизайн: минималистичный, mobile-first, Tailwind CSS.
```

## ЭТАП 2 — Словарь и управление контентом
*Цель: полноценная система управления словами*
### Шаг 2.1 — API словаря
```
Создай CRUD API роуты для словаря (защищены ролью EDITOR и ADMIN):
- GET /api/words — список слов с фильтрацией по topic, type, difficulty и поиском по kyrgyz/russian. Пагинация по 50 слов.
- POST /api/words — создать слово (поля: kyrgyz, russian, type, topic, pos, difficulty)
- PUT /api/words/[id] — обновить слово
- DELETE /api/words/[id] — удалить слово
- POST /api/words/import — принимает массив слов, проверяет дубли по полю kyrgyz, возвращает превью (сколько новых, сколько дублей) без сохранения. Добавь параметр confirm=true для финального импорта.
```
### Шаг 2.2 — Интерфейс управления словарём
```
Создай страницу /admin/words (только для EDITOR и ADMIN):
- Таблица слов с колонками: кыргызское слово, русский перевод, тип, топик, сложность, действия
- Фильтры сверху: по топику (dropdown), по типу, поиск по тексту
- Кнопка "+" открывает модальное окно с формой добавления слова (поля: kyrgyz, russian, type, topic, pos, difficulty)
- В каждой строке кнопки "Редактировать" и "Удалить" с подтверждением
- Пагинация снизу
Mobile-first дизайн на Tailwind CSS.
```
### Шаг 2.3 — Импорт через Excel
```
Добавь на страницу /admin/words секцию импорта Excel:
- Кнопка "Импорт Excel" открывает модальное окно
- Drag & drop зона или кнопка выбора файла (.xlsx, .csv)
- После выбора файла — парсинг через SheetJS на клиенте
- Показать превью: таблица с распознанными словами, количество новых и дублей
- Кнопка "Подтвердить импорт" — отправить на POST /api/words/import?confirm=true
- Показать финальный результат: сколько слов добавлено
Обязательные колонки: kyrgyz, russian, topic. Опциональные: type, pos, difficulty.
```

## ЭТАП 3 — Игровая механика
*Цель: рабочие сессии с вопросами*
### Шаг 3.1 — Алгоритм умного повтора и выборки слов
```
Создай модуль src/lib/algorithm.ts:
- Функция getWordsForSession(userId, mode, topic?, count) — возвращает слова для сессии
- Логика весов: слова с ошибками > 40% → вес ×2, не виденные > 7 дней → вес ×1.5, новые (0 показов) → вес ×1.5, хорошо усвоенные (>5 показов, ошибки <20%) → вес ×0.5
- Режим "random": берёт count слов с учётом весов из всего словаря
- Режим "repeat": только слова которые пользователь уже видел
- Режим "weak": усиленный акцент на словах с ошибками > 40%
- Режим "topic": слова только из указанного топика
Создай API роут POST /api/session/start — принимает mode и topic, возвращает подобранный список слов (без ответов статистики).
```
### Шаг 3.2 — Генератор вопросов
```
Создай модуль src/lib/questions.ts:
- Функция generateQuestion(word, allWords, direction, questionNumber) — возвращает объект вопроса
- Тип А (выбор из 4): слово на одном языке + 4 варианта перевода (1 правильный + 3 из того же топика)
- Тип Б (выбор из 2 похожих): используется если пользователь уже видел это слово (shown > 0)
- Direction: "ky-ru" или "ru-ky"
- Неправильные варианты для Типа Б — самые похожие по длине и первой букве слова из словаря
Создай API роут POST /api/session/answer — принимает wordId, answer, sessionId. Обновляет UserWordStat, возвращает правильный ответ и статистику.
```
### Шаг 3.3 — Экран сессии
```
Создай страницу /session с компонентами:
- Прогресс-бар сверху (вопрос X из N)
- Компонент QuestionTypeA — слово в центре + 4 кнопки вариантов
- Компонент QuestionTypeB — слово в центре + 2 кнопки вариантов
- После нажатия: подсветить правильный (зелёный) и неправильный (красный) варианты, кнопка "Далее"
- Анимации переходов между вопросами
- Кнопка выхода из сессии с подтверждением
Состояние сессии хранить в React state (текущий вопрос, счёт, список ответов).
Mobile-first, крупные кнопки удобные для нажатия пальцем.
```
### Шаг 3.4 — Экран результатов сессии
```
Создай страницу /session/results:
- Показать: правильных ответов / всего вопросов, процент, XP заработано
- Если новый уровень — анимация с поздравлением и новым званием
- Список слов где была ошибка (кыргызское + правильный перевод)
- Кнопки: "Ещё раз" (та же конфигурация), "На главную"
Создай API роут POST /api/session/finish — принимает sessionId и все ответы, рассчитывает XP по правилам, обновляет User.xp и User.level, возвращает итоговые данные.
```

## ЭТАП 4 — Dashboard и уровни по топикам
*Цель: главный экран и прогрессия по темам*
### Шаг 4.1 — Dashboard
```
Создай главную страницу /dashboard для авторизованного пользователя:
- Приветствие с username
- Карточка уровня: текущее звание, полоска XP (текущий/нужно до следующего уровня)
- Кнопка "Быстрая сессия" — открывает bottomsheet/modal с выбором режима (случайные / повторение / слабые места) и направления перевода
- Секция "Уровни" — горизонтальный или вертикальный список топиков
- Каждый топик-карточка: название, иконка, количество слов, статус (пройден ✅ / доступен / заблокирован 🔒)
Mobile-first, весь экран умещается без скролла на стартовом виде.
```
### Шаг 4.2 — Система прогресса по топикам
```
Создай логику прогрессии по топикам:
- API GET /api/topics — возвращает все топики с количеством слов и прогрессом текущего пользователя
- Топик считается пройденным если пользователь набрал ≥ 75% правильных ответов в сессии по этому топику
- Следующий топик разблокируется после прохождения предыдущего
- Первый топик всегда открыт
- API GET /api/topics/[topic]/status — возвращает статус топика для пользователя (locked/available/completed, bestScore)
Обнови страницу /dashboard чтобы отображать актуальный статус каждого топика.
```
### Шаг 4.3 — Страница профиля
```
Создай страницу /profile:
- Аватар (заглушка с инициалами username)
- Username и текущее звание
- Текущий уровень и XP прогресс
- Статистика: всего сессий, всего слов встречено, слов хорошо усвоено (ошибки < 20%, показов > 5), любимый топик (в котором больше всего сессий)
- Список пройденных топиков с лучшим результатом
- Кнопка "Выйти"
Все данные через API GET /api/profile.
```
